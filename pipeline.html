Analysis Pipeline

Complete documentation of the Platez plate analysis process — version

Pipeline Overview

Every plate analysis runs through a multi-pass pipeline. Each pass focuses on a specific aspect, and conditional passes only execute when earlier passes need refinement. Post-processing normalizes and cross-validates after each major pass.

Pass 1: Primary Plate Reading Always

The first pass sends the full plate image with a comprehensive prompt structured into 5 sequential steps. No taxonomy is injected at this stage — keeping the prompt lightweight improves character-reading accuracy.

Prompt Structure

  1. Step 1 — Vertical Edge Text: Inspect all four edges for text printed perpendicular (90° rotated) to the plate. Critical distinction: horizontal state names (e.g. cursive "California") are NOT vertical text. Only genuinely rotated text like "DP" or "DV" qualifies.
  2. Step 2 — Disabled/ISA Logo and Suffix: Detect wheelchair symbol, determine position (left/right/none). Critical DP vs DV distinction — the second character changes the entire classification.
  3. Step 3 — Plate Number and Spacing: Read center alphanumeric characters. Includes truncation check (cropped edges), spacing-first analysis (scan gaps before transcribing), and explicit anti-collapse rules for formatted output.
  4. Step 4 — Expiration: Read month sticker (usually top-left) and year sticker (usually top-right) independently. Month/year stickers are separate physical tabs. Convert abbreviations to integers.
  5. Step 5 — Spacing and Symbols: Classify separator types (full-space, half-space, bullet, hyphen), determine separator source (design vs assigned), and identify symbols in character slots.

Pass 2: Re-Read Conditional

Trigger Conditions

  • Plate number confidence < 0.7
  • Expiration month or year is null AND plate has mixed characters (letters + digits)

Behavior

Sends the image again with the Pass 1 result as context. The prompt focuses specifically on confirming/correcting the plate number and reading expiration stickers that may have been missed.

Merge Strategy

  • Plate number: Adopts Pass 2's value only if its confidence is higher than Pass 1's
  • Expiration: Adopts Pass 2's month/year if provided (non-undefined)
  • Confidence: Takes the maximum of both passes

Pass 2a: Corner Crop Sticker Reading Conditional

Trigger Conditions

Expiration month or year is still null after Pass 2.

Image Processing

FunctionCrop RegionScaleFilters
cropCorner()30% width × 30% height from corner4×contrast(2.2) brightness(1.1) saturate(1.5)

Sub-steps

  1. Month sticker (left corner): Asks model to identify a colored sticker tab with month text. Requires sticker_visible: true and confidence ≥ 0.5 before accepting.
  2. Month fallback (right corner): If left corner found nothing, tries the right corner.
  3. Year sticker (right corner): Same anti-hallucination pattern — must see an actual sticker with digits.

Anti-Hallucination

The model must explicitly confirm "sticker_visible": true before any value is accepted. If the model reports no sticker visible, the value stays null rather than being guessed. All sticker confidence is capped at 0.85.

Pass 3: Design Classification Conditional

Trigger Conditions

The detected state has taxonomy data in plate-types.json.

Taxonomy Injection

A flat numbered list of valid design types for the state is built from the taxonomy file. The model must pick one verbatim — no paraphrasing, no returning numbers.

Context Forwarding

  • Pass 1's design_type is provided for reference
  • Pass 1's variant_hint is provided as a "strong signal" — if it matches a taxonomy entry, the model is told to prefer it over generic types

California Visual Cues

California plates get extra classification guidance injected into the prompt:

  • BLACK background + gold characters + gold script "CALIFORNIA" → Legacy Black Plate (1963)
  • YELLOW/GOLD background + black characters → Legacy Yellow Plate (1956)
  • White/blue gradient → check for special interest art (Whale Tail, Yosemite, Lake Tahoe, Environmental, Arts Council, Breast Cancer, Pet Lovers, Firefighters, Collegiate)

Pass 4: Edge Crop for Vertical Text Conditional

Trigger Conditions

Plate is disabled (is_disabled: true) but vertical_text is still null.

Image Processing

FunctionCrop RegionScaleFilters
cropEdge()55% width strip from left/right edge, full height3×contrast(2.0) brightness(1.1) saturate(1.3)

55% width with overlap ensures the DP/DV text (between wheelchair icon and plate number) is captured from both sides.

Strategy

  1. Independent edge calls: Left and right edge crops are sent as separate model calls (not combined) to avoid image-order confusion.
  2. Candidate selection: Both sides' results are collected. Only valid suffixes (DP, DV, DPE, DVE) are accepted. The highest-confidence candidate wins.
  3. Full plate fallback: If edge crops fail, a final attempt uses the full plate image with a targeted prompt asking specifically about stacked vertical letters near the wheelchair icon.

Pass 5: Verification Always

Purpose

The model re-examines the original plate image alongside the complete analysis from all previous passes. It runs an 8-point verification checklist and can confirm or correct each field.

Verification Checklist

  1. Plate Number: Character accuracy, count, confusable characters (0/O, 1/I/L, 5/S, 8/B, 2/Z)
  2. Spacing: Do formatted separators match visible gaps? Standard sequential plates shouldn't have spaces.
  3. State: Correct identification from plate design/text
  4. Design Type: Accurate description of visual design features
  5. Expiration: Month/year match visible sticker tabs
  6. Disabled: Wheelchair/ISA symbol present or absent
  7. Vertical Text: Edge text (DP/DV) captured correctly
  8. Truncation: Any plate edge cropped in the image

Protection Rules

The verification pass has guardrails to prevent regression:

  • No null-outs: If a previous pass found a non-null value, the verification pass can change it to a different value but cannot erase it to null.
  • No false truncation: Cannot flip potentially_truncated from false to true.
  • Prompt reinforcement: The model is explicitly told not to second-guess uncertain-but-reasonable reads.

Discordance Detection

Before the verification pass runs, the current analysis state is snapshotted. After verification completes and values are applied, a field-by-field diff is computed. The result is stored in the _verification metadata:

{
  "_verification": {
    "corrections_reported": ["field1", "field2"],  // what the model said it changed
    "discordance": [                                // actual computed diff
      { "field": "plate_number", "before": "PR8042", "after": "R8042" },
      { "field": "design_type", "before": "Standard", "after": "Whale Tail" }
    ],
    "verified": false  // true if no discordance found
  }
}

Post-Processing Pipeline After Each Pass

The postProcess() function runs after Pass 1, Pass 2a, Pass 3, and Pass 5. It performs 30+ normalization, validation, and derivation steps.

Steps 1–5: Normalization
  1. Null-like strings: Convert "null", "n/a", "na", "none", "" → null for key fields (spacing_notes, vertical_text, plate_number, etc.)
  2. Confidence initialization: Ensure confidence object exists. Cap expiration confidence at 0.90 (stickers are inherently hard to read). Clamp plate_number confidence to [0, 1].
  3. dp_logo_position default: Set to "none" if missing.
  4. Infer is_disabled: If dp_logo_position is not "none", force is_disabled: true.
  5. Normalize vertical_text_position: Extract "left" or "right" from freeform strings; set to null if neither.
Steps 5a–5b: Expiration Normalization
  1. Strip parenthetical annotations: Model sometimes appends metadata to expiration — e.g. "15 (black)" → "15", "2015 (blue)" → 2015.
  2. 2-digit → 4-digit year: Numbers 0–99 become 2000–2099 (stickers often show just "10" meaning 2010).
  3. String year parsing: Handles string years, sets to null if unparseable.
  4. Month string → integer: Convert abbreviations (JAN→1, FEB→2, etc.) using the MONTH_MAP lookup.
Steps 6–8: Vertical Text Filtering
  1. Strip chrome labels: Remove known UI labels misread as vertical text: "MO", "YR", "MO YR", "MONTH", "YEAR", "STATE".
  2. Strip state name: If vertical_text matches the state name (e.g. "California"), it's a horizontal design element, not rotated text. Rejected with reason "state_name_horizontal".
  3. Hard filter — known suffixes only: Only DP, DV, DPE, DVE are allowed as vertical text. Everything else is rejected and preserved in _rejected_vertical_text for manual review.
  4. Move month/year from vertical_text (pass 1): If vertical_text contains month abbreviations or year patterns, extract them to expiration fields and null out vertical_text.
Steps 7–8: Formatted Plate Normalization
  1. Unicode escape replacement: Convert literal "U+0020", "U+00B7", "U+2022" to actual characters. Strip hyphenation points (U+2027).
  2. Bullet promotion: If separators says "bullet" but formatted string uses · (middle dot), promote to • (bullet).
  3. Content validation: Strip separators from formatted string and compare to plate_number. If they don't match (hallucinated content), reset formatted to plate_number.
Steps 8–8c: Disabled Plate Bleed Strips
  1. DP prefix bleed strip: On disabled plates, the model sometimes includes the DP/DV suffix at the START of plate_number (e.g. "DPR8042" → "R8042"). Strips the longest prefix that matches a suffix of the vertical text marker. Requires at least 3 characters remaining.
  2. DP suffix bleed strip: Same logic for the END of plate_number (e.g. "00000D" with vertical_text="DV" → "00000"). Strips trailing characters that are a prefix of the marker.
  3. Confidence re-evaluation: After stripping, pure-letter or pure-digit plates (no mixed characters) get a confidence floor of 0.9 — no inter-class ambiguity means high confidence.
Steps 9–10: Cross-Validation
  1. Move month/year (2nd pass): Catches date patterns in vertical_text not caught in step 13.
  2. Duplicate check: If vertical_text exactly matches plate_number (after stripping separators), clear it — it's a duplicate read.
Steps 10b–10e: Separator Logic
  1. Variant-level separator rules: _variantMeta in plate-types.json defines systematic separators for specific plate designs (e.g. Arizona 1996 legacy plates always have a bullet separator). If a variant match is found, the design-level separator overrides model-inferred values.
  2. Pattern-based spacing override: Known sequential plate formats (e.g. California "1ABC234", "ABC1234") never have spaces. If plate_number matches a known pattern, all separators are stripped from formatted string.
  3. Hallucinated per-character spacing: If every "group" in the formatted string is a single character (e.g. "R O K E R I J"), it's collapsed. Exception: short all-letter vanity plates (≤3 chars like "V X D") are preserved.
  4. Truncation confidence cap: If potentially_truncated is true, confidence is capped at 0.7.
Steps 11–17: Derivation
  1. Derive separators: Scan plate_number_formatted (source of truth) for space, ·, •, and - characters to build the separators array. Force separator_source: null when no separators present.
  2. Clean symbols_in_lpn: Remove nulls, empty strings, and common false positives from the symbols array. Preserve null (unknown) vs [] (confirmed none).
  3. Remove vertical_text from symbols: If vertical_text characters appear in symbols_in_lpn, remove them.
  4. Sync vertical_text_position: Force to null when no vertical text exists.
  5. Derive vertical_text_type: DP/DV/DPE/DVE → "plate_suffix". State name matches → "state_name". Otherwise → "decorative" or null.
  6. Derive disabled_type: Maps vertical_text suffix to human-readable type: DP→"Disabled Person", DV→"Disabled Veteran", DPE→"Disabled Person (Exempt)", DVE→"Disabled Veteran (Exempt)". Does NOT override design_type (they're separate fields).
  7. Sanitize design_type: Strip bracket-wrapped category headers (e.g. "[Standard Plates]" → null). Strip trailing bracket annotations.
  8. variant_hint → design_type promotion: If variant_hint matches a valid taxonomy entry for the state but design_type is still generic (e.g. "Standard Passenger Vehicle"), the hint is promoted to design_type.
  9. Derive registration_current: Compares expiration_month + expiration_year against today's date. Returns "Yes" (still valid through end of expiration month), "No" (expired), or "Unknown" (insufficient data).

Model List Fetching

  • LM Studio: GET /lm-models → proxied to LM Studio's /v1/models endpoint. Returns available models dynamically.
  • Gemini: Hardcoded list of vision-capable models (2.5 Flash, 2.5 Pro, 2.0 Flash, 2.0 Flash Lite).

Settings Persistence

All settings (provider, model, API key, LM Studio URL) are saved to localStorage under the key platez_settings and restored on page load.
